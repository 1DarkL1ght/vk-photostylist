# **Фотостилист - ВК-бот для автоматического подбора обработки фотографий**

_Агапова Александра, Ижденева Влада, Максимов Егор_

# Постановка задачи

Проект «Фотостилист» - это ВК-бот с агентом-диспетчером, который по текстовому запросу пользователя определяет, какой стиль обработки применить к присланной фотографии, и возвращает готовое изображение. Пользователь часто не знает точных терминов графических редакторов (например, «подними unsharp mask» или «S-кривую по контрасту»), но легко формулирует желаемый результат на естественном языке («сделай как в старом кино», «пусть будет ярче и сочнее»). Задача агента - понять свободную формулировку запроса и сопоставить её одному из заранее определённых стилей обработки, после чего вызвать соответствующий модуль обработки.

Архитектурное решение: в роли агента-диспетчера используется компактная instruction-модель Qwen (Qwen2.5-Instruct). В промпт агента зашивается полный перечень из 10 доступных стилей с описаниями; агент анализирует запрос пользователя и возвращает строго структурированный JSON вида {"style": "monochrome"}. Само значение style далее используется как ключ для вызова соответствующего Python-модуля - обработка изображения выполняется исключительно детерминированными алгоритмами классического компьютерного зрения, без повторного инференса нейросети на этом шаге.

Важное уточнение по учебным требованиям курса: пункт «Training framework» в задании обязателен (помечен звёздочкой) и подразумевает именно обучение нейросети, а не только промпт-инжиниринг готовой модели. Поэтому базовый (zero-shot) Qwen дообучается (LoRA/PEFT) на собственном датасете размеченных запросов - это дообучение и является тем нейросетевым обучаемым компонентом проекта, который логируется, конфигурируется через Hydra и сравнивается с бейзлайном по метрикам. Дообучение решает две задачи: (1) повышает точность определения стиля на реальных, в том числе русскоязычных, формулировках; (2) делает вывод модели надёжно валидным JSON без «болтовни» и лишних пояснений, что критично для автоматического парсинга.

Практическая ценность: решение даёт возможность обрабатывать фотографии в диалоговом формате без установки полноценных графических редакторов и без необходимости знать специальные термины - это особенно удобно на мобильных устройствах, где ВКонтакте уже является основным каналом общения у значительной части русскоязычной аудитории.

## Формат входных и выходных данных

Система состоит из трёх последовательных компонентов, у каждого из которых собственный формат входа и выхода:

| Компонент                                      | Вход                                                                                                                                      | Выход                                                                                                         |
| ---------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| ВК-бот (пользовательский уровень)              | Фото (jpg/png, произвольного разрешения) + текстовая подпись/сообщение с описанием желаемой обработки                                     | Обработанное фото в том же формате + текстовое сообщение с названием применённого стиля                       |
| Агент-диспетчер (LLM, Qwen)                    | Промпт = системная инструкция с полным перечнем из 10 доступных стилей (название + краткое описание каждого) + текст запроса пользователя | Строго структурированный JSON вида {"style": "monochrome"}; при нераспознанном запросе - {"style": "default"} |
| Модуль обработки изображения (классический CV) | Изображение в виде массива NumPy (H×W×3, uint8) + значение поля style из JSON                                                             | Обработанное изображение того же размера (H×W×3, uint8)                                                       |

Пример промпта агента-диспетчера и ожидаемого ответа:

| Роль                        | Содержимое                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| --------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| system                      | Ты - модуль классификации запросов на обработку фото. Тебе дан список из 10 стилей с описаниями. Определи, какой стиль просит пользователь, и верни СТРОГО JSON вида {"style": "<код\_стиля>"} без каких-либо пояснений. Если запрос не соответствует ни одному стилю — верни {"style": "default"}. Список стилей: monochrome, sepia, contrast, film\_grain, vignette, cool\_tone, warm\_tone, sharpen, soft\_focus, pixelate - с описанием каждого. |
| user                        | сделай фото как будто это старая плёночная камера                                                                                                                                                                                                                                                                                                                                                                                                    |
| assistant (ожидаемый ответ) | {"style": "film\_grain"}                                                                                                                                                                                                                                                                                                                                                                                                                             |

Итоговый видимый пользователю формат: на входе - фото + подпись в сообщении ВКонтакте, на выходе - обработанное фото, отправленное этим же ботом в ответном сообщении.

## Метрики

- Accuracy и macro F1-score определения стиля агентом на отложенной тестовой выборке запросов - основная метрика качества. Ориентир: macro F1 ≥ 0.85 при 11 классах (10 стилей + «по умолчанию»).
- JSON validity rate - доля ответов агента, которые являются синтаксически корректным JSON строго вида {"style": "<код>"} с кодом стиля из допустимого списка, без дополнительного текста. Ориентир: ≥ 0.98 после дообучения (у zero-shot-бейзлайна эта доля обычно заметно ниже за счёт «болтливости» модели и отклонений от формата).
- Confusion matrix - для анализа пар стилей, которые агент чаще всего путает (ожидаемо тяжелее всего разделяются близкие по смыслу пары, например «тёплый тон» / «сепия», «мягкий фокус» / «плёночное зерно»).
- Среднее время отклика бота (от получения фото до отправки результата) - нефункциональная метрика, важная для UX; ориентир - несколько секунд с учётом инференса LLM-агента.

## Валидация

Датасет текстовых запросов делится на train/val/test в пропорции примерно 70/15/15 со стратификацией по классу-стилю, чтобы сохранить распределение классов в каждой части выборки (классы потенциально несбалансированы - некоторые стили формулируются пользователями чаще других).

Для воспроизводимости разбиения фиксируется random seed через Hydra-конфиг, а сами индексы train/val/test сохраняются как артефакт и версионируются в DVC вместе с данными - это гарантирует, что при повторном запуске (в том числе другим членом команды или проверяющим) разбиение будет идентичным. На val-выборке отслеживается динамика метрик во время дообучения LoRA-адаптера (для ранней остановки и подбора гиперпараметров), test-выборка используется один раз - для финальной оценки агента.

Дополнительно на этапе валидации планируется ручная проверка (sanity check) небольшой случайной подвыборки ответов агента человеком - это позволит оценить, не «галлюцинирует» ли модель несуществующие стили и не переобучилась ли она на частотные ключевые слова в ущерб пониманию сути запроса.

## Данные

Для дообучения агента используются открытые датасеты, собранные из реальных пользовательских запросов на редактирование фотографий; каждый исходный запрос преобразуется в instruction-пример «промпт со списком стилей + запрос → целевой JSON-ответ»:

- Grounded Image Editing Request (GIER) - 30 000 пар «изображение + текстовый запрос на редактирование», собранных с сайтов Zhopped.com и Reddit (r/PhotoshopRequest). Источник: [arxiv.org/abs/2010.02330](https://arxiv.org/abs/2010.02330)
- PhotoshopRequests (Hugging Face) - около 20 000 реальных запросов на редактирование с сабреддита r/PhotoshopRequest. Источник: [huggingface.co/datasets/taesiri/PhotoshopRequests](https://huggingface.co/datasets/taesiri/PhotoshopRequests)

Из этих датасетов используется только текстовая часть запроса (сами изображения не нужны для обучения агента-классификатора). Каждый запрос размечается на один из 10 целевых стилей проекта либо помечается как «вне словаря стилей» и относится к классу default: часть выборки размечается вручную, остальная - полуавтоматически по ключевым словам с последующей выборочной проверкой. Целевой JSON-ответ для обучения формируется по шаблону {"style": "<код\_класса>"}.

Особенности и возможные проблемы данных:

- Оба датасета англоязычные, а целевая аудитория бота - русскоязычные пользователи ВКонтакте: потребуется перевод и/или сбор дополнительной русскоязычной выборки (например, ручной сбор небольшого количества примеров формулировок от знакомых пользователей) для дообучения на смеси языков.
- Запросы в исходных датасетах гораздо разнообразнее 10 выбранных стилей (включают сложные композитные правки вроде «убери человека на фоне») - такие запросы размечаются как класс default либо исключаются из обучающей выборки, если их доля слишком мала для содержательной разметки.
- Возможен дисбаланс классов (частотные формулировки вроде «сделай ярче» встречаются значительно чаще, чем узкоспециальные вроде «пиксель-арт») - компенсируется взвешиванием функции потерь при дообучении и стратифицированным разбиением.

# Моделирование

## Бейзлайн

В качестве простейшего решения используется тот же Qwen в zero-shot режиме - без какого-либо дообучения, с тем же промптом (список стилей + инструкция вернуть JSON), но без адаптации весов под задачу. Дополнительно рассматривается совсем простой небейзлайн-эталон - правило на основе ключевых слов (keyword/regex matching) без использования модели вообще, как нижняя граница для сравнения.

Оба варианта дают быстро получаемую нижнюю границу качества (по accuracy/F1 и по JSON validity rate), с которой в конце сравнивается финальный дообученный агент - прирост метрик после LoRA-дообучения должен быть статистически значимым, иначе дообучение не оправдано.

## Основная модель

Основная модель - агент на базе компактной instruction-модели Qwen2.5-Instruct (например, вариант 1.5B, при необходимости - 0.5B для ещё более быстрого CPU/GPU-инференса), дообученный методом LoRA (Low-Rank Adaptation) поверх замороженных базовых весов.

- Базовая модель: [Qwen2.5-Instruct (Qwen/Qwen2.5-1.5B-Instruct)](https://huggingface.co/Qwen/Qwen2.5-1.5B-Instruct) - компактная instruction-tuned модель с поддержкой генерации структурированного вывода.
- Дообучение выполняется методом [LoRA / PEFT](https://huggingface.co/docs/peft) поверх PyTorch: обучаются только низкоранговые адаптеры, что снижает требования к памяти и делает дообучение выполнимым на одной видеокарте уровня учебного проекта.

Промпт агента фиксируется как системная часть диалога и содержит полный перечень стилей с краткими описаниями (см. таблицу примера выше); формат вывода дополнительно ограничивается на этапе инференса (constrained/guided decoding по JSON-схеме или пост-валидация с одной повторной попыткой при невалидном ответе) - это снижает влияние остаточных ошибок формата после дообучения. Гиперпараметры дообучения (learning rate, ранг LoRA, число эпох, веса классов при построении обучающей выборки, seed) вынесены в иерархические Hydra-конфиги. Все метрики, гиперпараметры и git commit id обучающего запуска логируются в MLflow.

# Внедрение

Агент используется в составе ВК-бота: пользователь отправляет фото с подписью, бот передаёт текст в промпт агента, получает JSON с полем style, валидирует его и по значению style вызывает соответствующий модуль классического CV, после чего отправляет обработанное фото обратно в диалог.

- Интерфейс: VK Bot API - обработка входящих сообщений через Callback API или Long Poll API, отправка ответов через метод messages.send; со стороны Python - библиотека vkbottle или vk\_api.
- Инференс агента: дообученный Qwen с LoRA-адаптером разворачивается локально (transformers/vLLM) как отдельный сервис или как модуль в процессе бота - выбор между вариантами будет сделан по результатам замера времени отклика.
- Диспетчеризация: значение поля style из JSON используется как ключ в словаре «код стиля → функция обработки»; при невалидном JSON или неизвестном коде стиля применяется fallback-обработка (класс default - лёгкая нейтральная коррекция, например автоконтраст).
- Модуль обработки изображений (10 стилей на OpenCV/Pillow/NumPy) не требует отдельного сервиса и выполняется в процессе бота как обычная функция.

Дополнительный компонент, важный для проектирования кода: путь инференса агента (загрузка базовой модели + LoRA-адаптера, промпт-шаблон, валидация JSON) должен быть отделён от кода дообучения (data collator, PEFT-конфиг, обучающий цикл) и иметь минимальный набор зависимостей - это учитывается уже на этапе структурирования Python-пакета (отдельные модули train/ и infer/, разные наборы extras в зависимостях).
